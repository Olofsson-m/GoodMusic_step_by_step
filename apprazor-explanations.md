# AppRazor explanations

`AppRazor` is the ASP.NET Core **Razor Pages** front-end of the GoodMusic solution (.NET 10). Each page is a `.cshtml` template plus a PageModel class with handlers (`OnGetAsync`, `OnPostAsync`, ...), and pages call the shared service layer (`Services` → `DbRepos` → `DbContext` → database).
This document describes the code as it is in branch **`7-data-list`**, with the emphasis on what this branch adds compared with the previous branch, `6-data-overview`. The same feature exists in [AppMvc](appmvc-explanations.md); differences are pointed out.

---

## 1. This branch: List of music groups (compared with `6-data-overview`)

### Purpose
The previous branch showed *summary numbers* from the database (how many groups, albums and artists exist). This branch adds the first page that **reads the actual rows** and presents them as a list: a *Famous groups* page showing the names of the music groups stored in the database.

### Differences at a glance

| File | Previous branch | This branch |
|---|---|---|
| [Pages/ListOfGroups.cshtml](AppRazor/Pages/ListOfGroups.cshtml) | – | **new** page (route `/ListOfGroups`) |
| [Pages/ListOfGroups.cshtml.cs](AppRazor/Pages/ListOfGroups.cshtml.cs) | – | **new** `ListOfGroupsModel` PageModel |
| [Pages/Shared/_Layout.cshtml](AppRazor/Pages/Shared/_Layout.cshtml) | menu: Home, Static, Data overview, Seed | menu: Home, Static, Data overview, **Famous groups**, Seed |

No changes were needed in `Program.cs`: `IMusicGroupsService` was already registered in the DI container, and `MapRazorPages()` maps the new page automatically because the route comes from the file location (`Pages/ListOfGroups.cshtml` → `/ListOfGroups`).

### Request flow

```
Browser ──GET /ListOfGroups──► ListOfGroupsModel.OnGetAsync()
   │                              │ 1. ReadMusicGroupsAsync(seeded: true, flat: false, filter: null, page 0, size 1)  → only used for DbItemsCount
   │                              │ 2. ReadMusicGroupsAsync(seeded: true, flat: false, filter: null, page 0, size NrOfGroups) → all rows
   │                              ▼
   │                           MusicGroupsServiceDb ── 1:1 ──► MusicGroupsDbRepos.ReadMusicGroupsAsync(...)
   │                                                             │ EF Core query on MainDbContext.MusicGroups
   │                                                             ▼
   │                                                  database (tables MusicGroups, Albums, Artists)
   │                              ▲
   │                              │ ResponsePageDto<IMusicGroup> { PageItems, DbItemsCount, ... }
   │                           MusicGroups = PageItems; NrOfGroups = DbItemsCount → Page()
   ◄── HTML (Pages/ListOfGroups.cshtml inside _Layout.cshtml) ──┘
```

### The PageModel
```csharp
public class ListOfGroupsModel : PageModel
{
    readonly IMusicGroupsService _service;  readonly ILogger<ListOfGroupsModel> _logger;

    public bool UseSeeds { get; set; } = true;
    public List<IMusicGroup> MusicGroups { get; set; }
    public int NrOfGroups { get; set; }

    public async Task<IActionResult> OnGetAsync()
    {
        var _resp = await _service.ReadMusicGroupsAsync(UseSeeds, false, null, 0, 1);          // count only
        MusicGroups = _resp.PageItems;  NrOfGroups = _resp.DbItemsCount;
        _resp = await _service.ReadMusicGroupsAsync(UseSeeds, false, null, 0, NrOfGroups);     // all rows
        MusicGroups = _resp.PageItems;  NrOfGroups = _resp.DbItemsCount;
        return Page();
    }

    public ListOfGroupsModel(IMusicGroupsService service, ILogger<ListOfGroupsModel> logger) { ... }
}
```
- **Dependency injection:** the PageModel is created per request with the music-group service and a logger supplied by the container ("just like in the Web API"). It depends on the interface, not on the database implementation.
- **PageModel = view model:** the public properties `UseSeeds`, `MusicGroups` and `NrOfGroups` are what the page reads through `Model.*`. (AppMvc needs a separate `ViewModels/ListOfGroups` class for the same purpose.) They are plain properties without `[BindProperty]`: nothing is posted back, so there is nothing to bind.
- **Handler:** `OnGetAsync` runs for `GET /ListOfGroups`; it is `async` because the call chain down to EF Core is asynchronous, and returns `Page()` to render the template.
- **Two service calls:** the first call asks for a page of size 1 just to learn the total number of rows (`DbItemsCount`); the second asks for a page of exactly that size starting at page 0, i.e. *all* rows. This is a simple way to "read everything" with an API built around paging (`pageNumber`, `pageSize`).
- **Parameters of `ReadMusicGroupsAsync(seeded, flat, filter, pageNumber, pageSize)`:**
  - `seeded` = `UseSeeds` (default `true`): only rows generated by the seeder are returned – rows created by users (`Seeded = false`) are not shown. There is no UI control for this yet, so the list always shows seeded data.
  - `flat` = `false`: the repo uses `.Include(...)` to load each group's `Albums` and `Artists` too (eager loading). The list page only uses `Name`, so `true` (no includes) would be cheaper; the full objects are what later detail pages will need.
  - `filter` = `null`: treated as an empty string by the repo, i.e. no filtering.
  - `pageNumber` = 0, `pageSize` = number of groups.
- **What the repo does:** `MusicGroupsDbRepos` builds an `AsNoTracking()` query (read-only, no change tracking overhead), applies `Where(Seeded == seeded && (name/genre/year contains filter))`, counts the matches (`CountAsync`), then `Skip(pageNumber * pageSize).Take(pageSize)` and returns `ResponsePageDto<IMusicGroup>` with `PageItems` and `DbItemsCount`.
- **Return type `IMusicGroup`:** the service layer returns the interface from the `Models` project (name, genre, established year, albums, artists), so the web app does not depend on the EF entity classes in `DbModels`.
- **Limitations worth knowing:** the second call loads the whole table (fine for the seeded sample sizes, not for large data), the first call's `PageItems` are immediately overwritten, and `NrOfGroups` is stored but not displayed yet.

### The page
[Pages/ListOfGroups.cshtml](AppRazor/Pages/ListOfGroups.cshtml) starts with `@page` (makes it routable) and `@model ListOfGroupsModel` (the short name works because `_ViewImports.cshtml` sets `@namespace AppRazor.Pages`), and sets `ViewData["Title"] = "List groups"`.
- Header (`h2`) and an intro paragraph.
- A Bootstrap grid (`row` / `col-md-7 col-lg-10`) with a header row *Group Name* styled by `themed-grid-head-col` (from `wwwroot/css/grid.css`).
- A guarded loop:
  ```cshtml
  @if (Model.MusicGroups is not null)
  {
      @foreach (var item in Model.MusicGroups)
      {
          <div class="col-md-12 themed-grid-col">@item.Name</div>
      }
  }
  ```
  The `is not null` guard prevents a `NullReferenceException` if the list was never populated; each item becomes a full-width cell styled by `themed-grid-col`. Razor HTML-encodes `@item.Name`, so group names are safe to render.

### Layout and navigation
```html
<a asp-area="" asp-page="/ListOfGroups" class="nav-link">Famous groups</a>
```
The `asp-page` tag helper (enabled by `_ViewImports.cshtml`) builds the URL from the page path, so the link keeps working if the page moves or the routing is customised. All other menu and footer links use `asp-page` in the same way.

### Trying it
1. Make sure the database contains seeded data (use **Seed** if necessary).
2. Run AppRazor (profile `http` → `http://localhost:5183`) and open **Famous groups** (`/ListOfGroups`) – the names of all seeded music groups are listed, one per row.

## 2. Application structure (current)

```

├── AppRazor.csproj               References Configuration, Encryptions, Models, Services; Nullable disabled
├── Program.cs                    DI registrations and HTTP pipeline

├── app-seeds.json                Source data for SeedGenerator
├── Properties/launchSettings.json  Profiles http :5183, https :5001/:5000, IIS Express, AppMusicRazor
├── Pages/
│   ├── _ViewImports.cshtml       @using AppRazor, @namespace AppRazor.Pages, tag helpers
│   ├── _ViewStart.cshtml         Sets _Layout
│   ├── Index.cshtml (+ .cs)      Welcome page          -> /
│   ├── DataSourceInfo.cshtml (+ .cs)  Data overview    -> /DataSourceInfo
│   ├── ListOfGroups.cshtml (+ .cs)    List of groups   -> /ListOfGroups
│   ├── Members/Seed.cshtml (+ .cs)    Seed form        -> /Members/Seed
│   └── Shared/                   _Layout.cshtml, _LoginPartial.cshtml (empty placeholder), _ValidationScriptsPartial.cshtml
├── SeidoHelpers/SeidoHelpers.cs  Extension methods for model validation and enum select lists

```

### [Program.cs](AppRazor/Program.cs)
- **Services:** `AddRazorPages()`; `AddSecrets(env)` (user secrets or Azure Key Vault, chosen by `ApplicationSecrets:SecretStorage`); `AddEncryptions`; `AddDatabaseConnections`; `AddUserBasedDbContext`; `AddVersionInfo` and `AddEnvironmentInfo`; a named `HttpClient` "MusicWebApi"; scoped DbRepos and services (`IAdminService`→`AdminServiceDb`, `IMusicGroupsService`→`MusicGroupsServiceDb`, `IAlbumsService`→`AlbumsServiceDb`, `IArtistsService`→`ArtistsServiceDb`).
- **Pipeline:** `UseHsts` and `UseDeveloperExceptionPage` outside Development (shows detailed errors – to revisit before deployment), `UseHttpsRedirection`, `UseStaticFiles`, `UseRouting`, `UseAuthentication`, `UseAuthorization`, `MapRazorPages()`; aliases `/version` (JSON with version info) and `/static` (redirect to `/index.html`).

### [appsettings.json](AppRazor/appsettings.json) and launch settings
`ApplicationSecrets:SecretStorage`, `DatabaseConnections` (`DefaultDataUser`, `MigrationUser`, `UseDataSetWithTag`) and `DataService` (`DataSource`, `WebApiBaseUri`). Connection strings and credentials are kept in secrets. In `launchSettings.json` the `https` profile runs with `ASPNETCORE_ENVIRONMENT=Production` (and an extra `MyOwn` variable); `http`, `IIS Express` and `AppMusicRazor` run as Development.

### Layout, imports and footer
- `_ViewImports.cshtml` enables tag helpers (`asp-page`, `asp-append-version`, the form tag helper with antiforgery token) in all pages and layouts, and lets pages refer to models without full namespaces.
- `_Layout.cshtml` is the common page frame (title *AppMusicRazor*): favicons, Bootstrap and extra CSS, an SVG icon sprite, header menu (*Home*, *Static*, *Data overview*, *Famous groups*, *Seed*), footer and the Seido scripts. The *Static* link is a plain `href="~/index.html"` since it points to a static file. Unlike AppMvc, this layout does not contain the Bootstrap modals.
- The footer shows **Environment**, **Secret** (source and id) and **Data** (active data set tag and default data user), read from `IOptions<EnvironmentOptions>` – a quick check of which environment and database the app is talking to. No credentials are displayed.

### Data overview page
`DataSourceInfoModel.OnGetAsync()` calls `IAdminService.GuestInfoAsync()` and shows six counters (seeded/unseeded music groups, albums, artists) from the database view `gstusr.vwInfoDb`, mapped by `MainDbContext.InfoDbView`.

### Seed page
`Pages/Members/Seed.cshtml` + `Seed.cshtml.cs` (`SeedModel`); the `Members` folder is a natural place for protected pages later. `OnGetAsync()` loads `NrOfGroups`; `OnPostAsync()` validates the form, optionally removes all data (`RemoveSeedAsync(true)` and `(false)`), calls `SeedAsync(n)` (`SeedGenerator` + `app-seeds.json`: `n` groups with 2–4 albums and 2–4 artists each) and redirects to the data overview. `[BindProperty]` is used on `NrOfItemsToSeed` and `RemoveSeeds`, and Razor Pages validates the antiforgery token on POST automatically (the form tag helper emits the token).

### Other
- `SeidoHelpers.cs`: `ModelStateDictionary.IsValidPartially(...)` and `List<SelectListItem>.PopulateSelectList<TEnum>()`.
- `wwwroot/js/seido/modals.js` and `select-list-items.js`: data-attribute driven helpers for modals and selecting list items.

## 3. Comparison with AppMvc and next steps

| | AppMvc | AppRazor |
|---|---|---|
| List page | `GroupController.ListOfGroups()` + `ViewModels/ListOfGroups` + `Views/Group/ListOfGroups.cshtml` | `Pages/ListOfGroups.cshtml` + `ListOfGroupsModel` |
| Entry point | action method, found via `{controller}/{action}` route | `OnGetAsync` handler, route from the file path |
| View model | separate class in `ViewModels/` | the PageModel itself |
| Injected services | music groups, albums and artists (for later pages) | music groups only |
| Menu link | `asp-controller` + `asp-action` | `asp-page` |
| URL | `/Group/ListOfGroups` | `/ListOfGroups` |

Next: paging and searching in the list, view/edit/delete of a group, and authentication/authorization with the prepared pipeline.
